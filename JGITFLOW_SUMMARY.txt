🎯 GitFlow 工作流
==============================================================================

分支模型:

  master (main)     ←─ 生产版本 (3.3.7, 3.3.8...)
    │                  只包含正式发布版本
    │                  所有提交必须有 tag
    │
    ├─ release/x.x.x ←─ 发布准备分支 (3.3.7-RC.1)
    │                   从 develop 创建
    │                   用于发布前的测试和修复
    │                   完成后合并到 master 和 develop
    │
  develop           ←─ 主开发分支 (3.3.7-SNAPSHOT)
    │                  最新的开发代码
    │                  所有 feature 合并到这里
    │
    ├─ feature/xxx  ←─ 功能开发分支
    │                  从 develop 创建
    │                  完成后合并回 develop
    │
    ├─ hotfix/xxx   ←─ 紧急修复分支 (3.3.7.1)
                       从 master 创建
                       完成后合并到 master 和 develop

版本号规则:
  develop        → 3.3.7-SNAPSHOT      (开发版本)
  feature/auth   → 3.3.7-auth-SNAPSHOT (功能分支)
  release/3.3.7  → 3.3.7-RC.1          (发布候选)
  master (tag)   → 3.3.7               (正式发布)
  hotfix/3.3.7.1 → 3.3.7.1             (紧急修复)

【Step 1】修改配置 (15 分钟)

  1. 修改 gradle/libs.versions.toml:
     
     删除:
       [plugins]
       release = { id = "net.researchgate.release", version = "3.1.0" }
     
     添加:
       [plugins]
       jgitver = { id = "fr.brouillard.oss.gradle.jgitver", version = "0.10.0-rc03" }

  2. 修改 build.gradle (第 27 行):
     
     删除:
       alias(libs.plugins.release)
     
     添加:
       alias(libs.plugins.jgitver)

  3. 修改 build.gradle (删除第 546-560 行):
     
     删除整个 release 配置块:
       release {
           versionPropertyFile = 'gradle.properties'
           ...
       }

  4. 修改 build.gradle (在 plugins 后添加):
     
     jgitver {
         autoIncrementPatch = true
         useGitCommitId = false
         useDirty = true
         
         policy {
             pattern('master|main') {
                 transformations = []
             }
             pattern('develop') {
                 transformations = ['SNAPSHOT']
             }
             pattern('release/(.*)') {
                 transformations = ['RC']
             }
         }
         
         tagVersionPattern = 'v${v}'
     }

【Step 2】初始化分支 (10 分钟)

  $ git checkout -b develop
  $ git push origin develop

  $ git checkout origin/3.3
  $ git checkout -b master
  $ git push origin master

📖 日常使用
==============================================================================

【功能开发】
  $ git checkout develop
  $ git checkout -b feature/new-feature
  # 开发...
  $ git commit -m "feat: 新功能"
  $ git checkout develop
  $ git merge --no-ff feature/new-feature

【发布流程】
  $ git checkout develop
  $ git checkout -b release/3.3.7
  $ ./gradlew clean build test publish  # 版本: 3.3.7-RC.1
  $ git checkout master
  $ git merge --no-ff release/3.3.7
  $ git tag -a v3.3.7 -m "Release 3.3.7"
  $ git checkout develop
  $ git merge --no-ff release/3.3.7
  $ git push origin master develop --tags

【紧急修复】
  $ git checkout master
  $ git checkout -b hotfix/3.3.7.1
  # 修复...
  $ ./gradlew clean build test
  $ git checkout master
  $ git merge --no-ff hotfix/3.3.7.1
  $ git tag -a v3.3.7.1 -m "Hotfix 3.3.7.1"
  $ git checkout develop
  $ git merge --no-ff hotfix/3.3.7.1
  $ git push origin master develop --tags

⚠️ 重要注意事项
==============================================================================

【必读】
  1. JGitVer 需要完整的 Git 历史
     $ git fetch --unshallow  # 如果是浅克隆

  2. CI/CD 必须配置 fetch-depth: 0
     - uses: actions/checkout@v3
       with:
         fetch-depth: 0  # 重要！

  3. 分支保护规则必须设置
     - master: 只允许从 release/* 或 hotfix/* 合并
     - develop: 只允许从 feature/*、release/*、hotfix/* 合并

  4. 团队成员必须理解 GitFlow
     - 不要直接在 master 或 develop 上提交
     - 始终通过 feature/release/hotfix 分支

  5. 版本号由 Git 自动管理
     - 不要手动修改 gradle.properties 中的 version
     - 使用 Git 标签来标记正式版本

【可选】
  - 考虑使用 git-flow 命令行工具
  - 配置 IDE 的 GitFlow 插件
  - 设置自动化测试和部署
